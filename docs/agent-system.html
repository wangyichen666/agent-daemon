Rust · Personal Coding Agent

一个请求，如何变成一次可靠的代码行动

my-agent 是一个单用户、daemon 驱动的 AI 编码 Agent。CLI、本地 HTTP API 与编辑器 stdio 三个瘦入口连接同一个后台运行时；请求进入后再恢复记忆、组装上下文、规划、调用工具 或委派子 Agent，最后把同一份事件流和可核验结果返回给调用端。

3个对等瘦入口
8个可调用工具
1个状态真相 daemon
50轮 ReAct 上限
8路只读并发上限
能力边界 请求全流程 工具 进阶能力 记忆系统 安全与并行 代码架构 如何使用

02 / REQUEST FLOW

从请求进入，到回答离开

这条自上而下的链路是系统主干；发生工具调用时，第 6—10 步会循环。

01

任一瘦入口接收请求

请求可来自 CLI、/v1/chat/completions 或编辑器 stdio；入口只负责输入输出，不创建 Agent 运行时。

02

DaemonClient 发送统一 RPC

客户端经 Unix Domain Socket 发送 NDJSON JSON-RPC；单帧最多 4 MiB，并按 request id 多路复用事件与终态响应。

03

Daemon 接管状态并持久化

DaemonState 获取无超时 RAII turn 锁，把用户消息追加到 .my-agent/session.jsonl，并登记可取消的活动请求。

04

组装上下文

顺序固定为：系统提示 → 项目根目录的 AGENTS.md → 对话历史 → 动态 cwd / Git / 当前计划 / 技能。工具 schema 按名称稳定排序后作为 API tools 字段发送。

05

检查上下文预算

默认预算 32,000 token；超过 60% 时温和摘要最老部分，超过 85% 时强力压缩并保留最近 12 条，长文本分块递归合并。

06

流式调用模型

Provider 请求 OpenAI 兼容的 /chat/completions，逐行解析 SSE；文本增量立即变成 daemon 事件，工具 name / arguments 分片则完整重组。

纯文本
模型认为任务完成，转到第 11 步。
工具调用
进入参数、安全和执行链路。
07

工具查表与参数校验

ToolRegistry 按名称一次查表分发，并按工具 JSON Schema 校验参数。错误会作为工具结果返回给模型自行修正。

08

安全决策与审批

文件路径统一解析到绝对路径；工作区外读取拒绝，外部写入/编辑生成可挂起审批事件。CLI 可回答 y/N；无交互的 HTTP 入口安全地自动拒绝。

09

按波次执行工具

连续只读工具最多 8 路并行；write_file、edit_file、exec、remember、plan、sub_agent 等副作用工具逐个串行。

10

结果严格配对并回填

每个结果携带原始 tool_call_id 并落盘；图片另以仅本 turn 有效的 user 内容块发送。连续三次完全相同的调用和结果只会触发软提醒。

ReAct 回环：第 10 步回到第 04—06 步，最多循环 50 轮，防止意外无限调用。
11

保存最终回答

模型返回纯文本后，assistant 消息先追加到 session.jsonl，再作为本 turn 的结果返回。

12

同一事件流投影到入口

CLI 流式打印，HTTP 转成 OpenAI SSE，编辑器输出 JSON-RPC Event；最终 Response 到达后释放 turn 锁。Ctrl-C 发送取消请求，不杀 daemon。

03 / TOOLS

模型可以调用的 8 个工具

工具清单稳定传给模型；真正执行前仍要经过注册表、参数校验和安全策略。

read_file

只读 · 可并行

读取 UTF-8 文本、本地抽取 PDF；视觉模型启用时发送 PNG/JPEG/WebP 内容块。工作区外读取拒绝。

{ "path": "src/main.rs" }

exec

副作用 · 串行

通过 sh -lc 执行命令，返回退出码、stdout、stderr；单路输出超过 64 KiB 时截断。

{ "command": "cargo test" }

write_file

副作用 · 串行

创建或完整覆盖 UTF-8 文本文件。工作区外目标必须经用户审批。

{ "path": "notes.md", "content": "..." }

edit_file

副作用 · 串行

精确字符串替换。默认旧文本必须只出现一次；可显式设置 replace_all。

{ "path": "src/lib.rs", "old_text": "a", "new_text": "b", "replace_all": false }

remember

副作用 · 串行

把用户明确要求记住的偏好、约定或事实追加到长期记忆，可设置有效天数。

{ "content": "用户偏好中文注释", "ttl_days": 30 }

recall_memory

只读 · 可并行

使用英文关键词和中文相邻双字检索长期记忆，默认返回 5 条，最多 20 条。

{ "query": "注释偏好", "limit": 5 }

plan

副作用 · 串行

通过 set / update / add / show 整体重写、推进、追加或查看当前任务步骤，可选持久化。

{ "action": "update", "id": "2", "status": "done" }

sub_agent

副作用 · 串行

把自洽子任务放进全新历史执行；默认工具为 read_file / exec / recall_memory，最多 15 轮。

{ "task": "调研配置读取位置", "tools": ["read_file", "exec"] }
04 / ADVANCED

核心进阶能力如何协作

这些能力不是孤立开关，而是在一次请求的不同阶段共同控制目标、上下文、成本和执行质量。

目标管理

可重写任务计划

复杂任务先用 plan set 拆解步骤，执行前标记 in_progress，完成后标记 done。计划默认原子写入 .my-agent/plan.json，并在每轮动态上下文中可见。

上下文隔离

受限子 Agent

sub_agent 使用全新历史完成边界清晰的调研子任务，只把最终结论带回主对话。默认工具受限、最多 15 轮、不写主 session，也不能再次派生子 Agent。

成本优化

提示前缀缓存友好

系统提示、按名称排序的工具 schema 和项目规则保持稳定；对话历史居中，cwd、Git、计划和技能放在末尾。日志同时识别 OpenAI 与 DeepSeek 的缓存命中字段。

多模态

图片与 PDF

PNG/JPEG/WebP 以 OpenAI 兼容内容块交给视觉模型，base64 仅在当前 turn 存活。PDF 用本地解析器抽取最多 50 页文字；普通模型或不支持的格式会给出清晰降级说明。

稳定性

重复操作软提醒

连续三次出现相同工具名、参数指纹和结果指纹时，下一轮提示模型换思路或收尾；不会禁用工具，也不会把合法轮询误判成硬错误。

长对话

两级压缩闸门

默认 60% 水位只总结最老的一小段，85% 水位执行强力压缩并保留最近 12 条消息。原始 session 始终保持 append-only，摘要只改变内存请求视图。

工作方法复用

Markdown Skill 库

从 .my-agent/skills/*.md 建立标题与摘要索引，用英文关键词和中文 bigram 匹配当前请求，最多加载三个命中正文，避免一次塞入整个技能库。

边界

保持个人版克制

cron 与 MCP 仍是后续可选项；当前没有 RBAC、向量数据库、企业连接器或操作系统级沙箱。

运行时

工作区 Daemon

稳定工作区哈希隔离 socket/PID/ready/log；支持就绪探测、并发启动锁、自动拉起、stale 清理和无活动任务时的空闲退出。

控制面

事件、审批与取消

文本、工具、审批、完成均带 request id；审批可由另一个 RPC 恢复，运行中 turn 只接受显式取消，绝不按挂钟超时强杀。

05 / MEMORY

三种“记忆”不是一回事

系统把可靠恢复、控制上下文长度和跨会话偏好分成三条简单链路。

会话记忆

原始消息持久化

每条 user / assistant / tool 消息追加写入 session.jsonl。daemon 启动时自动恢复；CLI 的 /new 会把旧文件轮换成时间戳备份。

默认：.my-agent/session.jsonl
压缩记忆

长上下文摘要

60% 水位温和总结最老部分，85% 水位强力压缩。摘要只改变当前内存视图，原始 JSONL 仍可审计。

中文约 1.5 字符 / token · 英文约 4 字符 / token
长期记忆

可召回事实与偏好

remember 明确保存，recall_memory 按关键词、中文 bigram、手动标记和时间排序；过期条目不会返回。

默认：.my-agent/memory.jsonl
重要边界：长期记忆不会自动塞进每一次请求。模型需要根据工具描述主动调用 recall_memory；当前没有 embedding、向量数据库或自动语义检索。
06 / SAFETY

软安全边界与执行顺序

这是面向个人工作区的防误操作机制，不是容器、namespace 或 seccomp 级沙箱。

操作策略典型行为
工作区内读取直接允许可进入最多 8 路的连续只读并行波次。
工作区外读取拒绝不弹审批，避免并行读取争抢终端输入。
工作区外写入 / 编辑人工审批终端显示绝对路径，默认选择为 N。
灾难性 shell 命令硬阻断包括根目录递归删除、mkfs、块设备覆盖、fork 炸弹等。
高风险但可能合理人工审批包括 kill / pkill、sudo、git reset --hard、cargo publish 等。
普通写工具与 exec串行执行保持工具调用原始顺序，减少相互干扰。
非回环 HTTP 监听Token 必需必须设置 MY_AGENT_API_TOKEN；默认只监听 127.0.0.1。
07 / ARCHITECTURE

单 crate，清晰模块边界

仍是一个可执行 crate，但运行时收拢在 daemon，三个入口只通过统一客户端和协议访问它。

main.rs / config.rs

Clap 子命令、工作区选择、配置聚合检查与首次使用引导。

daemon/

DaemonState、协议 SSOT、handlers、审批、运行时装配、生命周期和 Unix socket server。

client.rs

持久 Unix 连接、request id 多路复用，以及测试用内存回环传输。

entry/

CLI REPL、本地 HTTP/SSE 和编辑器 stdio 三个瘦入口。

provider.rs

消息协议、Provider trait、OpenAI 兼容请求、SSE 文本和工具调用解析。

loop_engine.rs

ReAct while 循环、50 轮上限、并行波次、工具结果回填与最终终止判断。

context.rs

上下文排序、项目规则、动态环境、token 估算、分块总结与递归压缩。

safety.rs

所有文件路径和命令的单一安全决策点；审批由 daemon 中介挂起和恢复。

session.rs

append-only JSONL、残缺末行恢复、会话轮换，以及无超时的 RAII turn 锁。

memory.rs

长期记忆条目、有效期、关键词和中文 bigram 索引逻辑，以及两个记忆工具。

plan.rs

任务步骤状态、原子 JSON 持久化、动态上下文块与 plan 工具。

sub_agent.rs

复用 ReAct 核心，提供独立历史、工具子集、轮次预算和禁止递归的子 Agent。

skills.rs

Markdown 标题/摘要索引、关键词与中文 bigram 匹配，以及按需正文注入。

tools/

Tool trait、HashMap 注册表、参数校验，以及 read / exec / write / edit 实现。

08 / USAGE

构建、配置、运行

API 密钥、服务地址和模型名全部从环境变量读取，不应写入源码或提交到 Git。

# 1. 构建
$ cargo build --release

# 2. 配置 OpenAI 兼容服务
$ export OPENAI_API_KEY='你的密钥'
$ export OPENAI_BASE_URL='https://api.deepseek.com'
$ export MODEL_NAME='deepseek-v4-flash'

# 3. 可选：调整上下文
$ export CONTEXT_TOKEN_BUDGET='32000'
$ export CONTEXT_RECENT_MESSAGES='12'
$ export CONTEXT_MILD_PERCENT='60'
$ export CONTEXT_STRONG_PERCENT='85'

# 视觉模型名含 vision 时自动启用，也可显式设置
$ export MULTIMODAL_ENABLED='true'

# 4. 检查配置并运行 CLI
$ ./target/release/my-agent config check
$ ./target/release/my-agent

# 5. 其他入口
$ ./target/release/my-agent serve --bind 127.0.0.1:8787
$ ./target/release/my-agent editor
  1. 在希望 Agent 操作的项目目录中启动；该目录就是安全工作区。
  2. CLI 会探测并自动拉起当前工作区 daemon；历史由 daemon 自动恢复。
  3. 审批出现时核对完整命令或绝对路径，再输入 y；回车默认拒绝。
  4. 复杂任务可要求“先制定计划”；大范围调研可要求“交给子 Agent，只返回结论”。
  5. 要求记忆时明确说“记住……”；需要偏好时可明确说“先回忆……”。
  6. 可把工作方法写入 .my-agent/skills/*.md，标题使用一级标题，摘要使用 summary:。
  7. REPL 支持 /help、/status、/sessions、/new、/cancel、/exit；运行中按 Ctrl-C 发送显式取消。
示例任务：“读取 README 并总结”“运行 cargo test，定位失败原因并修复” “先规划并为项目补测试”“派子 Agent 调研配置读取位置”“读取设计截图并指出问题” “把我偏好中文注释记住”。模型会根据任务选择规划、工具、子 Agent、记忆或 skill。
